Section 2: Data Pipeline

Four data sources, all free, two already wired up. Each feeds a different part of the feature layer.

Source What we fetch Frequency Stored as Status
Alpaca Historical OHLCV daily bars, 5yr, S&P 500 (500 symbols). Adjusted for splits + dividends. Daily top-up (append yesterday's bar) data/prices/AAPL.parquet — one file per symbol. Parquet replaces CSV: 10× faster reads on 500 files. ✓ Extend existing
Alpaca News API Headlines + body snippets per ticker. Rolling 90-day window. Same API key, already authenticated. Daily (fetch overnight news before market open) data/news/YYYY-MM-DD.parquet — one file per day, all tickers. Columns: ticker, headline, url, published_at, source. ✦ New
FMP API Quarterly EPS actuals vs analyst estimates. Free tier: 250 calls/day — enough for quarterly updates. Quarterly refresh (after earnings season ends). Cached locally. data/earnings/earnings.parquet — all tickers, all quarters. Columns: ticker, date, actual_eps, estimated_eps, surprise_pct. ✦ New
yfinance (VIX) ^VIX daily close. Used by the regime filter in the risk engine. No API key needed. Daily top-up data/vix.parquet — single file, date-indexed. ✦ New
S&P 500 list Current constituent tickers + GICS sectors. Scraped from Wikipedia. Updated quarterly to handle additions/removals. Quarterly data/sp500_tickers.csv — ticker, company name, sector, sub-industry. ✦ New

One important design decision: parquet over CSV

At 500 symbols × 5 years × daily bars, CSV reads become slow and wasteful. Parquet is a columnar binary format — reads are ~10× faster and files are ~5× smaller. Python's pandas.read_parquet() works identically to read_csv(). The existing CSV files in data/ get replaced on the first run of the new ingestion script.
