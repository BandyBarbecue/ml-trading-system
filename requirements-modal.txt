# requirements-modal.txt — the container's dependency stack, pinned to match
# the laptop EXACTLY.
#
# requirements.txt is deliberately loose (pandas>=2.0, scikit-learn>=1.3, ...)
# because on the laptop it is only ever used to set up a fresh venv. On Modal
# it is resolved fresh on every image build, so loose bounds silently pick up
# whatever is newest on PyPI that day. On 2026-08-09 that produced pandas 3.0.5
# against the laptop's 2.3.3 — a MAJOR version jump, with copy-on-write and
# default string dtype changes, underneath a codebase that does heavy pandas
# work in feature_matrix.py. It also picked up a NEWER anthropic (0.121.0 vs
# 0.107.1) and an OLDER shap (0.51.0 vs 0.52.0), so the drift ran both ways.
#
# The migration's whole premise is that it changes WHERE the code runs and
# nothing about WHAT it computes. An unpinned dependency stack breaks that
# premise silently — the run still reports success, the numbers just differ.
#
# Regenerate after any deliberate local upgrade:
#     .venv\Scripts\python.exe -m pip freeze
# and update both this file and the laptop together, as one decision.
